# 하네스 설계와 운영

## 현재 구현 범위

현재 macOS 환경에서 Codex CLI를 반복 호출하는 개발 하네스다. Python은 명령행·OS 서비스 인터페이스를, Rust는 상태 변경·저장·프로세스 실행·스케줄링을 담당한다.
`AgentExecutor` 포트와 Codex 어댑터를 분리하고, 도메인 전이와 SQLite 저장소를 별도 모듈로 구성했다.

역할 정의는 리더가 참고하는 전문 관점이다. 현재 여러 에이전트를 병렬 실행하는 것은 아니며, 구현과 검토를 별도 Codex 세션으로 실행한다.
Claude Code에는 공통 지침을 제공하지만 자동 실행 어댑터는 아직 없다. Windows 자동 시작 등록과 실제 Windows 실행 검증도 후속 작업이다.
제품의 UI, MCP 서버, 전체 SDK 연동, 제품용 온톨로지는 후속 Task에서 구현한다.

## 상태 전이

| 단계 | 성공 | 실패/중단 |
| --- | --- | --- |
| meeting | 1~3개 Task 생성, 첫 Task 선택 | blocked/complete이면 1시간 후 재평가 |
| implement | verify로 전이 | 보고된 실패는 Task 재시도 횟수 증가 |
| verify | 설정된 명령이 모두 성공하면 review | 실패 시 구현으로 복귀, 완료 처리 금지 |
| review | 증거를 포함한 성공 보고 시 Task 완료 | 피드백을 포함해 구현으로 복귀 |

Task별 구현·검토·검증 실패가 합산 3회 누적되면 blocked로 기록하고 다른 Task 또는 회의로 이동한다.
재회의는 기존 실패 이유를 읽고 접근법을 바꾸도록 지시받는다. 동일한 실패의 의미를 자동 판정하는 것은 아직 모델의 판단에 의존한다.

모델 응답은 JSON Schema를 요청하고 Rust에서 필수 내용과 단계별 조건을 다시 확인한다.
구현 성공만으로 완료되지 않으며, 실제 검증 명령의 종료 코드와 별도 검토가 필요하다.
프로젝트 전체 완료 선언은 이후 주기적 재평가로 이어지며, 완료 상태에서 불필요한 작업을 생성하지 않도록 지시한다.

## 중단과 재시도

- 사용 한도 오류는 5분부터 최대 1시간까지 간격을 늘려 같은 단계를 재시도한다. Task 실패 횟수에는 포함하지 않는다.
- CLI 오류 이벤트 및 stderr로 한도 오류를 분류한다. 계정의 정확한 충전 시각을 조회하는 API는 사용하지 않는다. 따라서 회복 후 다음 재시도 때 재개되며 즉시 감지는 아니다.
- 인증 오류는 일시정지한다. `codex login`으로 해결한 후 `resume`한다.
- 기타 실행/출력 오류가 연속 3회 발생하면 일시정지하고 원인을 기록한다.
- 단계 실행은 기본 40분으로 제한한다. 시간이 초과하면 자식 프로세스 그룹을 종료하고 오류로 기록한다.
- pause/SIGTERM/Ctrl+C는 실행 중인 프로세스 그룹을 종료한다. 미완료 단계와 파일 변경을 보존한다.
- SQLite WAL 체크포인트로 다음 프로세스가 같은 단계에서 시작한다. 세션 ID에 의존하지 않고 Task·피드백·파일·최근 회고를 새 세션에 전달한다.
- 실행은 at-least-once다. 보고서 저장 직전 중단되면 같은 단계가 다시 수행될 수 있으므로 구현자는 기존 변경을 먼저 확인한다.
- OS 파일 잠금으로 중복 실행을 막는다. Unix에서는 자식이 잠금을 상속해 감독 프로세스가 비정상 종료되어도 자식이 끝나기 전 중복 작업을 방지한다.

macOS는 사용자 LaunchAgent로 실행한다. 로그인 후 시작하고 프로세스 종료 시 재실행하며, 일시정지 상태는 재시작 후에도 유지한다.
서비스를 켜는 것과 절전을 막는 것은 다르다. 현재 서비스는 전원/절전 정책을 변경하지 않는다.

## 기록과 학습

SQLite 테이블:

- `checkpoint`: 버전이 있는 현재 단계, Task ID, 회의 번호, 담당 역할, 수락 기준, 상태, 실패 횟수, 피드백, 최근 교훈.
- `runs`: Run ID → Task ID, 단계, 시작/종료 시각, 상태, 증거 디렉토리.
- `events`: 시각, 이벤트 종류, 해당 시점의 체크포인트 스냅샷.
- `control`: 운영자가 변경하는 일시정지 상태.

모든 실행은 별도 디렉토리에 프롬프트와 결과를 남긴다. 성공한 보고서의 교훈은 다음 단계에 전달한다.
이는 모델 가중치 학습이 아니라, 증거·회고를 바탕으로 코드·Skills·개발 절차를 개선하는 구조다.
현재 체크포인트는 개발 이력의 초기 구조이며 제품용 온톨로지 구현을 대체하지 않는다.
로그 보존/압축, DB 스키마 마이그레이션, 검색 가능한 증거 인덱스는 후속 과제다. 현재 기록은 자동 삭제하지 않는다.

## 실행 범위

Codex는 사용자 전역 설정을 자동 상속하지 않고 기존 로그인과 CLI 기본 모델을 사용한다. 모델은 `harness/config.json`에서 지정할 수 있다.
구현은 workspace-write, 회의/검토는 read-only sandbox에서 실행하고 웹 검색을 활성화한다.
자동 승인 요청은 사용하지 않는다. 허용된 작업이 sandbox에서 실패하면 우회하지 않고 결과에 기록한다.

규칙은 로컬 구현·테스트·조사를 허용하며 외부 게시·구매·메시지 전송과 목표/운영 권한 변경을 금지한다.
이 규칙은 모델 지침이며, workspace-write 내부의 파일별 접근 제어를 제공하는 것은 아니다.
실행 엔진은 Task의 지시로 설치된 실행 파일이나 서비스 설정을 자동 교체하지 않는다. 변경 적용은 운영 명령으로 한다.

## 검증

`python3 harness/cli.py check`는 Rust 테스트와 Python CLI 테스트를 실행한다.
Rust 테스트는 실제 SQLite 재시작, 중복 잠금, 한도 대기, 반복 오류 일시정지, 테스트 실패 시 완료 방지, 가짜 실행기를 통한 전체 상태 순환, 실제 자식 프로세스의 시간 제한·중단을 확인한다.
Python 테스트는 공백이 있는 경로를 포함한 LaunchAgent 직렬화와 비밀 환경변수의 서비스 설정 유입 방지를 확인한다.
LLM의 장시간 생산성과 한도 회복의 실계정 동작은 이 테스트만으로 보장하지 않는다.
